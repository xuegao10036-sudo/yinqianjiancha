  [修复] 网页下载的安装包双击后弹「安装失败」+ 几行 "'xxx' 不是内部或外部命令"
   · 雪糕反馈: "双击安装后提示这个，实际已经安装成功了"。两个独立缺陷叠在一起:
       ① 仓库里的 .bat 存的是 LF。cmd.exe 缺 CR(回车)时按块读文件, 含中文注释的行
          会错位, 注释被当成命令执行 —— 症状正是 'ut' / 'pause`' / 半行中文
          "不是内部或外部命令", 脚本跑到最后几行就散架。
          根因: .gitattributes 写的是 `text eol=crlf`, 但它只在 **git clone/checkout**
          时转换, 网页 Download ZIP **不应用 eol 转换**, 打出来的就是仓库里的原始内容。
          ⇒ 改成 `*.bat -text`, 仓库里直接存 CRLF(改 .bat 请用 _push.js 推, 它会强制转)。
       ② 仓库镜像不含 images/ ⇒ 从网页下载的包里根本没有这个目录。旧脚本无条件
          `xcopy images` 再无条件校验 icon.png ⇒ 必然置 FAIL 弹"安装失败",
          而 CSXS/css/js/jsx/index.html 其实都复制到位了(所以面板能正常打开)。
          ⇒ 改成"存在才复制、存在才校验", 缺图标只在控制台留一行提示, 不判失败。
   · 顺带修: 只有注册表写入失败时也让窗口停住(原来那段 FIX 提示一闪而过看不到),
     并且 "All done" 与 "registry switch FAILED" 不再同时打印。
     mac 一键安装.command 同款 images 容错(校验里去掉 icon.png)。
   · 测试: 新增 bt125(本地 bat 全 CRLF / .gitattributes 用 -text / 两处容错 / 提示互斥 /
     mac 同款), 主回归 225/0; 反验 4 项(回退成 LF、退回 eol=crlf、恢复无条件 xcopy、
     恢复无条件 cp)全红, 复原全绿。
   · 已实测: 用隔离 APPDATA 真跑安装脚本 —— LF 版能复现 'pause`' 报错; 修复后
     "有 images" 与 "无 images" 两条路径都打印 OK - files copied, 落盘文件齐全。

v11.56  (2026-10-29)
  [修复] 五项"看着通过、其实没查"的问题(全量只读审查后集中修)
   · ① 清理时锁错对象(pfCleanup)
        现象: 隐藏对象恰好位于锁定组内时, 清理完可能把**原本没锁**的对象锁上。
        根因: pfBlockInfo 只上报"最近的阻挡节点" node —— 它可能只是隐藏节点,
              更远的祖先才是锁定的那个。pfCleanup 拿 node 当锁节点去解锁/回锁,
              解的是没锁的, 锁的也是没锁的 ⇒ 用户状态被改坏。
        修法: 锁定/隐藏**分别记最近的那个**(lockedNode / hiddenNode), 原有
              reason/node 语义保留(pfClearBlock 仍按 node 解除)。
   · ② 色板判"未使用"的两处误删风险
        ②-a 专色/图案/渐变解析失败被判未使用(pfSwatchUsed)
             根因: 解析 swatch 失败时 return false(=未使用)。损坏文档、特殊色板会踩。
             修法: 解析失败一律 return true(保守当在用)。
        ②-b 采集"不完整"却照删(pfUsedColorKeys)
             现象: 部分文字/对象颜色读失败, 面板仍给绿字"无未使用", 删除也照执行。
             修法: 新增 incomplete 标记 —— 深度超限、组件遍历失败、色值分量读不出、
                   文字按字符区间采色失败都置真; 两个删除入口见到 incomplete 直接
                   拒绝并写明原因; 卡⑧改报"统计失败"而不是绿色通过。
             另: 文字颜色改为按 textRanges.characterAttributes 逐区间采集(混合文字、
                 局部专色不再被整帧读取吞掉), 拿不到 textRanges 才回落整帧。
   · ③ 分辨率"读不到"被静默丢弃 ⇒ 卡⑤ 假通过
        现象: 有图读不出 ppi 时, 总数里没有它, 面板照样"全部达标"。
        修法: 计入 total 并单独累加 unknownCount; 前端见到 unknownCount>0 或
              truncated 即报"未完成"徽标, 并明确写出有几张无法判定及原因。
   · ④ 卡⑦ 把"近白"和"纯白"混成一个数
        现象: 分级版说"需处理 N 个", 但说不清其中多少是真纯白(CMYK 全 0)。
        修法: 新增 whiteClass(CMYK 原值和 < 1), 与精确 0 的 white 分开累加;
              分级版卡改用它, 简洁版口径不变。
   · ⑤ 卡⑥/卡⑨ 定位漏掉子图层(pfLocGather)
        现象: 二级及更深**子图层**里的问题对象点定位选不中。
        根因: Layer 分支只递归 pageItems, 没递归 it.layers。
        修法: 子图层一并下钻(同样受 depth 上限保护)。

   · 雪糕: "图片未嵌入, 分辨率 300 也会被选中"。

        定位端卡⑤ 都改调它, 保持同源。
        · 读不到文件(缺失 / 网络盘 / 认不出的格式) ⇒ 退回原 matrix 算法, 不崩不改行为。
        · 对象被旋转/剪裁时(宽高比与像素比偏差 >15%) ⇒ 同样退回 matrix 算法 ——
          包围盒尺寸不再等于画布尺寸, 用错配的边硬算会制造新的误报。

v11.6  (2026-10-20)
  [修复] 「重置默认」只回一半 —— 雪糕反馈"这个重置默认的按钮是不是坏了？"
   · 现象: 点重置后 出血 3 / 极小字号 6 / 分辨率 300 / 油墨偏重 220 都回到默认(这几项他从没改过),
         但 油墨总量超标 301、色版低于 20、描边细于 1 纹丝不动 —— 而这正是他自己改过的三项。
         看起来像按钮"只重置了一半"。
   · 根因: 渲染时那句 `if (!TH_DEF) TH_DEF = d.th` 把 jsx 回传的**生效值**(用户改动已叠加在上)
         当成了"出厂默认值"缓存; 而 `!TH_DEF` 又保证它只写一次、永不更正。
         于是第一次扫描之后,"默认值"就等于"用户自己的设置", 重置自然只能回到原处。
   · 修法:
     ① 渲染只更新生效值 PF_TH, 不再写 TH_DEF —— 默认值的唯一来源是 jsx 的 pfThDefaults();
     ② thEnsure 增加 force 形参, 每次打开设置弹层都重取一次默认值(纯内存拷贝: 不扫文档、
        不重新解析脚本)。老面板里已经存着的脏默认值, 打开一次设置就自愈, 不必重启面板;
     ③ 重取是异步的, 回调可能落在用户已经开始输入之后 ⇒ 加 TH_DIRTY 守卫, 不回盖手输的值;
     ④ 万一默认值真取不到(jsx 异常), 重置提示改成"未能读取默认阈值…", 不再假装成功。

          "用户切换了文档", 从而全量重扫一遍(大文档每次白转 5~20 秒)。原因: 检查结果里的
          docPath 写的是 "(文档尚未保存)", 而轻量探针 pfDocKey 写的是 "(未保存)", 前端按
          \`!==\` 比对两者永远不等。现把探针的哨兵改成与检查结果逐字一致的 "(文档尚未保存)"。
          ② 油墨"色版 1~4%"块的排序加固 —— 该块样本没有 total, 两侧都被兜成 -Infinity 时
          \`tb - ta\` 会算出 NaN; 比较器返回 NaN 是规范未定义行为(当前只是 V8 恰好把它当作
          0 才保住稳定序)。现显式写 \`if (ta === tb) return 0;\`。显示顺序完全不变。
          ③ jsxFilePath() 结果缓存 —— 扩展路径在会话内不变, 原实现却每次 execJsx(含每次
          面板获得焦点的 pfDocKey 探针)都白跑一遍 getSystemPath + decodeURI + replace,
          快路径上算完即丢。现缓存一次; 首次读取失败(空串)时不写缓存, 留给下次重试。
